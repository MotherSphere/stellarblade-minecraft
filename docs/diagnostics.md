# Diagnostic commands

The gameplay path is [`/stellarview play`](../README.md#start-a-session). The commands below isolate problems; they are not required for each session. F10 belongs to the existing Stellar Blade console. Shift may also trigger native dodge; prefer console equivalents when keeping EVE still.

## Stellar Blade

| Key | Console command | Action |
|---|---|---|
| F5 | `sbmc mirror` | Import the active Minecraft collision window (Minecraft: `/stellar import`) |
| F8 | `sbmc enter` | Enter the created lab once (Minecraft: `/stellar enter`) |
| F6 | `sbmc status` | Log context, position, loaded World Composition tiles and timing counters |
| F11 | `sbmc restore` | Revoke input, stop captures, return EVE and clean up owned geometry (Minecraft: `/stellar return`) |
| F4 | `sbmc framehd` | One 1280 × 720 paired still: BMP color, PNG mask, HDR depth |
| F2 | `sbmc depth` | Independent depth probe; not paired with another capture |
| F1 | `sbmc live` / `sbmc liveoff` | Legacy 320 × 180 animated diagnostic; capped at 60 seconds or 300 frames |
| F7 | `sbmc create` | Standalone collision fixture: floor, four walls, step and obstacle |
| F9 | `sbmc toggle` | Toggle the standalone fixture's obstacle |
| Shift+F7 | `sbmc texture` | Toggle a non-colliding stone-texture probe |
| Shift+F8 | `sbmc visuals` | Toggle native Minecraft terrain visuals inside Stellar Blade |

Minecraft's `/stellar import`, `/stellar enter` and `/stellar return` run the F5, F8 and F11 actions through a [session request](../protocol/README.md#session-requests), one at a time. Lua logs `Request: import N from Minecraft` before the action's own `OK:` or `STOP:` line, `Request: enter N refused: ...` when the sessions do not match (nothing runs), `Request: answer not written: ...`, and `STOP: Session requests paused: ...` for an unexpected failure. Minecraft shows the answer in chat and logs `Session request N import: ok: ...` (or `failed`, `refused`), or `Session request N import: no answer` after 5 seconds, which is when Stellar Blade is not running or runs a Lua revision before 48. A refused import usually means `/stellar start` was run again after Stellar Blade read the terrain; enter is refused without a link of the same session, and return only while another session is linked, so use F11 for a link Minecraft no longer knows.

`sbmc posetest` records EVE's skeletal mesh components for up to 15 seconds or 900 frames: bone transforms relative to their parents (`SnapshotPose`, with a per-bone fallback), face morph weights and component world transforms. It writes private `eve-pose-probe.txt` (components, bones, method, timing) and `eve-pose-probe.bin` (per frame: frame number, seconds, then each component's world transform followed by its bones and weights, 10 floats per transform). It changes nothing in the scene; Minecraft can replay it with [`/stellaravatar replay`](#avatar-view-experimental).

`sbmc frame` retains the 320 × 180 PNG still; `sbmc framehdpng` retains HD PNG color. `sbmc capture` is an independent color probe. `sbmc capturecleanup` retries failed capture cleanup.

`sbmc exportbmp` compares synchronous color exports. `sbmc exportasync` and `sbmc frameasync` share one asynchronous submission attempt per Lua lifetime and omit completion callbacks. The latter requires Minecraft's file-close watcher already running, then `/stellarpreview load` or `/stellarview load`. Pending generation files are retained until cleanup with both games closed. `sbmc exporttest` is disabled because its callback crashed the pinned loader.

Read `SB/Binaries/Win64/ue4ss/UE4SS.log`, prefix `[StellarCollisionProbe]`, and Minecraft's `logs/latest.log`. Successful object creation or texture assignment is not proof of valid pixels or collision.

The terrain window: Minecraft logs `Terrain revision=N boxes=B window=[x, y, z] publish=T ms` for each new revision (the window's centre cell; T includes the scan, the merge and the write), and `Terrain window held at cell [x, y, z]: reason` with the action-bar warning, at most every 5 seconds, while a move cannot be made. `/stellar status` adds the block in the middle of the window and the slowest publication. Lua logs `Importing Minecraft collision revision N: K boxes left.` when a revision does not fit one frame's 4 ms budget, then `Minecraft collision revision N: A boxes added, R removed, K kept in T ms over F frames; reused U, spawned S, slowest op O ms.` (`; window moved` after a move; U and S count the actors placed, a moved window's six guards included: U moved into place from those earlier revisions parked, S spawned once none is left, so after the first move S stays 0 unless the new window has more boxes than were parked; O is the slowest single placement or parking), `Window move deferred: EVE is outside the new window.`, `... a new guard intersects EVE.` or `... the new window would leave the world.` (retried with each packet), and `Terrain import waiting: new geometry intersects EVE.` while a queued box waits for her to move. UE4SS's own `Asset loaded` line marks the diagnostic cube mesh loading: once per Lua load (again only if the engine deleted it after a return), not once per box.

The lab site and Stellar Blade's streaming: F6 logs `World Composition tiles loaded: L of N; streaming follows the camera` (or `pinned at (X,Y)`), the tiles Stellar Blade has loaded, read from its World Composition; `World Composition tiles unavailable: ...` on a level without it. The Great Desert has 151: about 110 are loaded around EVE's usual area, and about 1 (the sky) once she has entered the lab at its remote site. F5 there ends with ` Lab at the remote site -750000 -750000.`, or ` Lab above EVE: streaming pin unavailable: ...` when Stellar Blade did not accept the streaming pin the return needs, in which case the lab is built above EVE as on other maps. On other maps F8 pins streaming at EVE's start and adds ` Streaming not pinned: ...` if that failed (harmless: Stellar Blade then streams around its camera as before). Returning from the site, F11 or `/stellar return` first answers `Waiting for Stellar Blade to stream the return point.` (Lua logs it once more, then nothing while it waits), then Lua logs `Returned after waiting T s for the return point to stream and removed ...`. T does not count time Stellar Blade spent paused, when it streams nothing; ` (one forced load)` after `stream` means the ground was still missing after 10 s and Lua forced one blocking load before returning her.

## Minecraft views

- `/stellarpreview load` shows a still on a checkerboard; `/stellarpreview off` closes it.
- `/stellarview load` composes a still against world depth. It requires the matching entered terrain session and revision.
- `/stellarview live` consumes the legacy F1 producer. `/stellarview livehd` requests the continuous raw producer without input forwarding.
- `/stellarview status` reports image delivery separately from Minecraft FPS; see [performance measurements](#performance-measurements). `/stellarview off` restores the normal camera and stops forwarded controls.

Still captures expire 30 seconds after capture. Legacy live startup times out after five seconds; two seconds without a fresh generation stops an established view. A repeated frame does not renew freshness. Revision changes hide incompatible frames. Unsupported effects, session/world changes or invalid data stop composition.

A high Minecraft FPS counter with slow EVE motion indicates a different capture/transfer cadence; compare accepted frames over the same interval and framebuffer size. A small checkerboard preview does not show the full capture resolution. Hair noise can originate in native capture, not only the Minecraft compositor.

## Avatar view (experimental)

These commands draw EVE with her own meshes in Minecraft. Minecraft keeps its own camera, frame rate, lighting (lightmap at EVE's position, entity-style directional shading) and fog. Under open sky by day, the sun takes over part of that directional shading and EVE shadows herself; her shadow falls on the block faces around her along the sun (straight down without it, as Minecraft's entity shadow), in third person, unless the Entity Shadows option is off. Her materials add normal maps, ambient occlusion, roughness-based highlights, reflections of Minecraft's sky (in proportion to the sky light where she stands), metals, emissive parts and light scattered under the skin on top of that lighting; hair cards get strand highlights, darker roots and soft strand edges blended over what lies behind them, and translucent overlays (eye occlusion, catchlights, the wet tear line) draw last.

- `/stellaravatar replay` loops the latest `sbmc posetest` recording from the bridge directory two blocks ahead of the player, interpolating between recorded frames. Stellar Blade does not need to run.
- `/stellaravatar live` streams EVE's current pose from Stellar Blade (Lua revision 54 and the matching adapter) once per native frame. After `/stellar start`, F5 and F8 she stands where the bridge places EVE and replaces the player's body in third person; Minecraft hides her in first person, where the camera is inside her head. Without an entered link she stands two blocks ahead of where the command ran. A changed composition (outfit, weapon, hair) briefly reloads meshes and textures.
- `/stellaravatar play`, after `/stellar start`, F5 and F8 and without `/stellarview`, drives EVE from Minecraft without any capture. Minecraft owns the camera (third person by default) and its mouse look; Minecraft's movement and action bindings are forwarded as with `/stellarview play`, gated by a fresh streamed pose instead of a captured image. While input is forwarded, the adapter turns Stellar Blade's camera toward Minecraft's at each native frame: yaw through the game's own look input, as a mouse would, pitch by setting the game's camera dolly from the camera's own pitch (through look input instead while the game's camera follows the controller, eases or lags its rotation, uses another dolly spline, aims, fishes or runs its slope camera). Each pose reports the controller's rotation; the left stick is rotated by any remaining difference so EVE moves where Minecraft looks. If the camera does not follow (a yaw gap above 30 degrees for a second), the right stick steers it instead (full deflection at 45 degrees of yaw error, never reversing during fast spins). `/stellaravatar status` reports the share of poses turned by look input and the mean and maximum yaw gap, then the share of poses whose dolly the adapter set and their mean and maximum pitch gap (Minecraft's pitch against the game camera's, read one native frame earlier). When the adapter left the camera's pitch to pitch input, `Pitch input instead: ...` names the three commonest reasons with their share of controlled poses (aim, another camera spline, slope camera and so on). The camera follows EVE's displayed position.
- `/stellaravatar status` reports the stream: component-table generation, poses received per second, incomplete poses, the age of the last pose, the adapter's read time (last, maximum and mean microseconds per native frame, including the copy into the shared slot) and the streamed meshes left out of the newest pose (`Not drawn now: ...`: hidden in Stellar Blade, such as EVE's drone between its appearances, or without data). `Cloth: N of M poses used Stellar Blade's ponytail cloth (P particles); S stale samples (particles unchanged while her head moved).` counts the poses that drew her ponytail from Stellar Blade's cloth rather than its bones (`bones now` instead of the particle count while the displayed pose has none) and the cloth samples that did not move while her head did; a stale run of 6 samples falls back to bones until the cloth moves again, so S that keeps rising means Stellar Blade stopped ticking the cloth. `Cloth: none in the component table.` means Lua flagged no ponytail (short ponytail or none). Once per stream run Lua logs `Cloth: SBPonytail tick option T, blend weight W, simulation disabled B` before the world-drawing cut changes the tick option (3 is `OnlyTickPoseWhenRendered`, set to 1 during the cut); a blend weight below 1 means Stellar Blade mixes skinned and simulated hair, which Minecraft does not. Its combat part ends with `Drone shots: C counted, F fired here, H hits.`: the adapter's shot count since it loaded, the shots Minecraft drew while EVE was the bridged player, and those that met an entity. The Minecraft log names the first 20 shots of a stream as `EVE drone shot N: from the drone|hand|eyes, hit <entity>|a block|nothing at D blocks` (`hand`: no drone part drawn; `eyes`: first person, or neither a drawn drone nor EVE's right hand in the pack). Just before the drone shots, `Minecraft earned Beta N, Burst M.` counts the base points Minecraft's strikes, parries and kills earned since Minecraft started, before EVE's rates and caps. After the stats, `Gauge gains: the adapter granted Beta B, Burst U.` is what the adapter actually added to her gauges since it loaded, after her rates, caps and the Burst unlock (points earned while it did not read Minecraft's words never land), and `Heals: H Stellar Blade HP converted; mirror off|on|held; L Stellar Blade losses overwritten.` counts the HP Stellar Blade's heals added above the mirrored value (Minecraft heals the same share of its maximum), says whether Stellar Blade's HP carried Minecraft's share at the latest poll (`on`), waits for Minecraft to apply a heal or for a fresh share (`held`) or is Stellar Blade's own (`off`), and counts the Stellar Blade-side HP losses the mirror overwrote.
- `/stellaravatar off` removes her and releases the stream.
- `/stellaravatar shading entity` draws her through Minecraft's entity programs, as under a shader pack, to compare without Iris; `/stellaravatar shading auto` returns to her own shaders unless a pack is in use. `/stellaravatar status` ends with which one draws her.

Each command reports drawn material sections, meshes missing from the pack and, for a replay, loading time. With `/stellaravatar live` alone, drive EVE in Stellar Blade; `/stellarview play` also works but adds its captured image and image-paced camera. Poses are displayed one sample interval behind the newest, interpolated on Stellar Blade's publication times, so motion stays smooth above Stellar Blade's frame rate; `/stellaravatar status` shows that interval.

The renderer reads a private avatar pack from `~/.local/share/stellar-blade-minecraft/avatar` (override with `-Dstellarbridge.avatar=<dir>`). The pack is built from the user's own game installation and is never part of this repository:

- `<mesh>.sbav` for each mesh named in the recording's `COMPONENT` lines. Components without a mesh in the pack are skipped and listed.
- `<material slot>.png`: one baked RGBA base texture per drawn section; alpha below 0.5 is cut out, and its mipmaps keep the share of texels that pass, so thin strands do not thin out at a distance. Hair slots then blend what the cut-out dropped over the opaque image without writing depth, so strand edges are smooth; overlapping soft edges are not sorted. Sections without a PNG are not drawn.
- Optional maps beside it, each falling back to a neutral default: `<slot>.normal.png` (tangent-space normal in Unreal's convention, +X along +U and +Y along +V; the shader builds the frame from screen-space derivatives, so meshes need no tangents), `<slot>.surface.png` (occlusion, roughness, metallic and specular in R, G, B, A; specular 0.5 is 4 % reflectance), `<slot>.emissive.png` (RGB added after lighting), `<slot>.scatter.png` (subsurface color times mask: light wraps past the terminator along the smooth normal) and `<slot>.hair.png` (root-to-tip gradient, strand id and depth; selects strand shading along +V).
- `<slot>.overlay.png` instead of `<slot>.png` for a translucent slot: premultiplied RGB with its opacity in alpha (alpha 0 adds light), drawn after every opaque section without writing depth; without its own surface map it gets no highlight. `<slot>.glow.png` is such an overlay drawn only while the slot's streamed `Opacity` is above zero, its emissive map tinted by `Emissive_Color` × `Emissive_Intensity` plus the `_2` pair.
- `<mesh>.trail.txt` beside a weapon mesh: `SBAVTRAIL 1`, `BEGIN bone x y z` and `END bone x y z` (the trail sockets in Unreal units in their bones' space), `HELD mesh handBone centimeters chestBone`; with `<mesh>.trail.png` (gradient in red, streak noise in green).
- `fx.<texture>.png`: Stellar Blade's own effect textures (sparks, flares, rings, lightning arcs, wind streaks), glow in red. Without them, Minecraft particles stand in for the game's effects.
- `hud.<texture>.png`: Stellar Blade's own HUD textures, square: the Tachy slot (`Tk_Idle_Base2`, `Tk_Idle_Icon`), the Tumbler's cup (`potion`), the dash slot (`skill_hud_dashframe`, `Skill_Icon_Dash`), the bullets (`bullet_icon_01` to `_05`) and the util items (`Icon_Camera`, `Icon_PotionR`, `Icon_Potion`, `Icon_PotionSmall`, `HealGrenade`, `Grenade`, `PluseGrenade`, `TrapGrenade`, `FlashGrenade`, `WbPump`), each read once per Minecraft run. Without one, fills or a vanilla item stand in.
- The wardrobe's icons, also as `hud.<texture>.png`: each item's own icon (white line art, which the screen tints) and the screen's own (`icon_equipment_color`, the orange "E" badge; `EquipLock`; the empty-slot silhouettes `ExospineNormal`, `CommonGearDim`, `Lookfocus_Icon00` to `03` and `Lookfocus_Icon06`). Without one, the slot's silhouette, or a fill and a letter, stands in.
- `wardrobe.txt`: the catalog of Stellar Blade's wardrobe items, UTF-8, read when the wardrobe screen opens: `SBAVWARDROBE 1`, then one tab-separated line per item (the `ItemTable` ID, `ESBItemCategory`, alias, `ESBItemRarityType`, icon texture or `-`, the largest bone count of its meshes, its meshes as comma-separated file names without `.sbav` or `-`, name and description in the game's language), then `END` and the item count. Another version or any malformed line drops the whole catalog: the screen then names items `#<id>`, with their slot's silhouette.
- `pack.txt`: the game files the pack was built from: `SBAVPACK 1`, `PAKS <Stellar Blade's Paks folder>`, one `SOURCE <path under it> <bytes> <mtime in ns>` per `.pak`, `.utoc` and `.ucas` file the builder mounted (base game and mods), `MESH <file>.sbav <object path> <container>` lines, `END`. Each `/stellaravatar live` or `play` compares the `SOURCE` lines with that folder (sizes and times only) and, when they differ, logs and shows once `Avatar pack built for other Stellar Blade game files (+added, -removed, ~changed, ...): rebuild the pack with both games closed. EVE is still drawn.`; a mod added, removed or updated, or a game patch, causes it. An unreadable or other-version manifest gives `Avatar pack manifest ... unreadable`. Without `pack.txt` (a pack built before mod tracking), or while the Paks folder is absent (its drive not mounted), nothing is compared.

`SBAVMESH` version 2 is little-endian, in Unreal space (centimeters, Z up): magic `SBAVMESH`, `u32` version; `u32` bone count (at most 256), then per bone a `u16`-length UTF-8 name, `i32` parent (earlier bone or -1) and the reference local transform (10 floats: quaternion xyzw, translation, scale); `u32` vertex count, then 56-byte vertices (position, normal, UV, four `u16` bone indices, four float weights); `u32` index count and `u32` triangle indices; `u32` section count, then per section a material slot name, first index and triangle count; `u32` morph count, then per morph a name, `u32` delta count and per delta a `u32` vertex with position and normal deltas (6 floats). Morphs follow the mesh's Unreal `MorphTargets` order and are matched to recorded weights by name. Recorded bone names must equal the mesh's bones in order; leader-pose followers (face, ponytail) map bones by name to their leader.

The live stream carries the face's morph weights (expressions, blinks); `sbmc posetest` recordings do not. It also carries glow parameters the game animates on dynamic material instances (`Opacity`, `Emissive_Intensity`, `Emissive_Color` and their `_2` pairs): a `<slot>.glow.png` slot such as the sword's edge appears only while its `Opacity` is raised. `/stellaravatar status` lists how many parameters are streamed and the highest glow opacity seen. Most of Stellar Blade's combat effects are not material parameters but particle systems its attack shows spawn (anim trails between weapon sockets, Niagara effects such as the sword flame buff). The sword's trail is a short ribbon (0.12 s by default) between the weapon's trail sockets with the game's trail gradient. While effects are streamed it follows the game's own Cascade trails (`P_A_AnimTrail_*`): it draws only while one plays, with that trail's emitter colors and lifetime (white fading to blue for light slashes, a longer white for strong ones, bluish thrusts). Without effect data it falls back to the swing: while the blade is in EVE's right hand and turns fast relative to her chest. The game's other effects on EVE are particle components the world pools and attaches to her skeletal components while they play. Lua publishes how to read them (reflected offsets and the effect assets: the sword's main ones once loaded, then any seen active) and the adapter reports up to eight active ones each frame with their world transform. Minecraft redraws them as additive sprites with the game's textures, one recipe of emitters per asset approximating its Niagara emitters: sparks streaking from the blade (`NS_A_ParTrail_*`), the charged heavy attack's red horizontal flare, lens flare, sparks and crystal shards (`*HoldBurst_Signal*`), a red ring with orange sparks (`*HoldBurst_SwordFX*`), blue lightning arcs along the blade (`*Electric*`), flares for draws and kicks, wind streaks around EVE for spins, mesh trails and charged slashes, a small flare otherwise. Without `fx.*` textures it spawns Minecraft particles there instead. `/stellaravatar status` counts known effects and poses with active ones. Lua also logs every change of EVE's active effects to `UE4SS.log` as `EVE effects: asset[class]@parent:socket ...`, counting only effects Stellar Blade draws (active and visible). EVE's drone, a separate Stellar Blade character, streams with her: its skeletal mesh (`CH_NPC_Drone` or the equipped skin) is drawn from its own pose where the private pack has that mesh, only while Stellar Blade draws it, and its attached effects count among hers. Lua logs each change of the drone's state as `EVE drone: <object> actor shown|hidden, mesh visible|invisible (found in N ms)`, or `none` while no drone exists. Minecraft follows only those flags: a drone Stellar Blade hides another way (a material fade, moving it away) still shows, and an object name that changes between its appearances means the game replaces the drone rather than toggling it (each change rebuilds the avatar's model once). Its effects are logged but take none of the 32 effect asset slots yet. `./gradlew avatarRenderCheck -PavatarCheck="<pack> <recording dir> <out.png> <seconds,...> [distance,height,degrees[,target] [glow | fx=asset+asset] [sun=elevation,azimuth] [entity]]"` in `minecraft/` renders a pack and recording offscreen with the same renderer and prints per-mesh extents; `tile=WxH` sets each tile's pixels, for instance a wardrobe preview rectangle at the GUI scale, whose camera this is; `fx=` plays those effect assets at the blade for 0.2 s before each frame. `cloth=FILE` (after the camera argument) draws the recording's `SBPonytail` component from one cloth frame as the adapter streams it (little-endian floats: `ComponentRelativeTransform`, then the simulation-space particles), prints how far the drawn vertices lie from that cloth through a CPU copy of the vertex shader and, at the first time, the per-frame CPU cost of the cloth path (pose blend, deltas and normals, a draw with a new cloth against one with the same), then fails unless the deltas read back from the GPU are those it checked, with the cloth, after a fallback drops it (the morphs again) and once it is back; `bones` with it draws the bones instead and prints their distance from the cloth. It needs a GPU and is not part of `tools/check.py`.

Lua logs each combat event it acts on as `Combat: kind seq [from yaw deg]; show ...; effects ...` (a failed Show or effect says why); a perfect dodge logs EVE's animation state before the Show (`before: custom alpha A; move block N; move type T; input F/R`), 0.2 s later `Combat: perfect_dodge seq: Stellar Blade plays it; +0.2s: ...` or `... show not seen; time at 0.30; effects ...`, and `Combat: perfect_dodge seq +0.6s: ...`, then `Combat: time restored` after a fallback; a perfect parry logs both Shows (`show P_Eve_Sword_Normal_Guard1_JustParry ...; show Result_JustParry_FX ...`, with `effects NS_JustParry_02` only when the latter failed), a guard `show Result_Guard_Back... toward the side (deg), hit-level check lifted`, and each of them, like a parry, `Combat: kind seq +0.6s: custom alpha A; ...` (a custom alpha above 0 means the Show animates EVE); `Combat: lifted Show key not restored yet, retrying: ...` until a lifted key comes back; a hit or a strong hit (`hit_strong`) adds `reaction library|gate|tag ..., attack from the front|back|left|right (relative deg), Result_Hit_Stand_LightAttack|Result_Hit_Stand_StrongAttack` (the Show played, with `(strong Show unavailable: why)` after the light one when a strong hit fell back to it; or why the reaction failed) and 0.3 s later `Combat: hit|hit_strong seq variant: head moved N cm; custom alpha A; additive alpha B; speed S cm/s` with `reaction kept` once a variant animates EVE, `inconclusive, EVE was already animating|moving` for a try that is not counted, or `no variant animated EVE, reactions off` after twelve counted tries, at most 200 lines per Lua lifetime. `/stellaravatar status` shows `Evades: unlocked F first, D double, C cut; locked F first, D double, C cut; N evade commands, R lock evade rows changed by the lock.`: Stellar Blade's own evade starts since the adapter loaded, as her command tree records them (a Show Lua plays, such as the perfect dodge or the lock's sword draw, is not one), split by whether the adapter applied Minecraft's lock. First counts every Evade-command row of her stance, so an air dodge, a fast getup or an Evade-command attack (flash-behind, move-back) adds one too; double counts her combo children (the double dodge); cut counts first dodges whose combo window (0.8 s for the sword evades) closed more than 0.2 s before its end, as when a skill outside her tree starts. N is how many lock-gated evade commands the latest locked frame changed (4 with the sword stance: both lock-on evades opened, both plain ones closed). R is how many of the seven lock evade rows (their turn toward the stick and their second rule move's turn toward a target) the latest lock start left at 0: 7 when the adapter found them all in Stellar Blade's tables, 0 when it found none (a registry layout it does not know), in which case it wrote nothing. For a double tap: one first and one double means the double dodge started; one first and one cut, that its window closed before the second press could take it; one first with neither, that the second press was not taken while the window was open; two firsts, that her tree went back to its root and the first row was taken again; a double counted without the expected animation points at the Show. The line is in the session's stop summary in Minecraft's log too. It ends with `Gauges: Beta current/max, Burst current/max` (`(locked)` before Stellar Blade unlocks Burst) or `Gauges not read.` when the adapter cannot reach the player actor, then `Stats: max HP H (health xA), attack P (strikes xB), critical C% xD, N shield blocks; hits taken xM melee, xR ranged.` with the latest stats Stellar Blade gave and what Minecraft makes of them (the health and strike multipliers, the share of a hit's damage EVE takes), or `Stats not read.` before the adapter could read them. Lua logs the lock-on as `Lock: proxy ..., tribe T for EVE tribe P, controller none`, `Lock: engaged: ...` followed by `Lock: near: ...` (Stellar Blade's characters within 35 m of EVE horizontally, her and the proxy excepted, as `name tribe T at X Y Z (d cm, bearing B, hidden H)`, or `none within 3500 cm`: without a simulation lock target, a lock evade's second rule move would turn her toward the nearest enemy of them within 30 m), once a second `Lock: held, N relocks, C soft clears: ...` (C counts the frames where Lua cleared Stellar Blade's soft lock-rotation disable) and `Lock: lost N: ...` when Stellar Blade drops it, each with `IsLockOn`, the AnimBP's `IsLockOn`, EVE's facing and the camera's angle off the target, the distance, her forward and sideways speed, the off-screen timer, movement mode and the flags Stellar Blade checks, the camera dolly (`dolly 0..1`, where 1 frames her from her hips), `battle B sword State@Socket` and `soft S rotoff R` (the soft lock-rotation disable, which holds her facing until a move key, and how many lock-rotation-disabling skill steps run), plus `Lock: sword N/5: drawing|instant draw with <unfold Show> [<weapon row>, ponytail shown|hidden] (sword was State@Socket)` for each draw (or the error that stopped it) and `Lock: sword: sheathing with <fold Show> [...] ...`, `already sheathed ...` or `left to Stellar Blade ...` on release; the bracket names the EquipmentTable row read from EVE's `EquipmentDataList` at `EquipmentType_Weapon` (the list follows `ESBEquipmentType`) and her `bHidePonyTail` (`weapon X unknown, stock pair` or `unread` when Lua fell back to LightSword1's Shows, and `; <Show> failed: why` when the chosen Show did not play and LightSword1's played instead) (after an attack while locked, the held lines keep `battle true` until the release, where `left to Stellar Blade` comes before Stellar Blade's own sheathe about 3 s later), then `Lock: released (reason): ...` (at most 300 lines; `held` and `lost` lines stop after 200). While locked, `LockTrace: t T facing F yaw Y at X Y target X Y vel F R rotoff N soft B skill B turning B input F R` lines sample EVE's facing on their own budget (at most 2000 per Lua lifetime, about 80 dodges): on the first locked frame, at a clear (` (cleared)` after `soft`), when rotoff, her running skill (`bRunningSkill`) or her idle turn (`bIdleTurning`) changes, when her yaw moved 3 degrees or more since the last line, and every 0.1 s while rotoff is above 0. t is Lua's clock in seconds, yaw and the positions are Unreal's, vel is her forward and sideways speed and input her last MoveForward and MoveRight inputs. In a locked first dodge rotoff reads 1 from the press to its last step's end (about 1.7 s, earlier with a move key; a double dodge's own steps leave it at 0) and the yaw stays within a few degrees of its value before the press; a `(cleared)` line at the end means Stellar Blade kept her facing frozen and Lua released it, and extra ones right after a step boundary, with rotoff back at 1 at once, only show that Stellar Blade ends a step before starting the next. Combat (see the README) adds a line to `/stellaravatar status`: strikes landed, then perfect parries, parries, perfect dodges, dodges, guarded hits and hits taken. A strike counts once Minecraft accepted its damage; a defense counts once per attack (repeats within half a second keep the first verdict) for damage to the bridged player from an attacker or projectile while the link is live, in survival, and a hit only once it lands. Lua logs once per Lua lifetime the functions and properties named like combat (damage, hit, evade, parry, guard, actor state, time dilation and the like) on EVE's class chain and her components' classes, as `EVE combat: function Class.Name` or `EVE combat: property Class.Name` lines in `UE4SS.log` (at most 300): the starting point for Stellar Blade's own hit reactions and defensive state.

Lua logs the mob walls as `Mobs: first wall spawned, blocks channel N` (N is the object type of EVE's capsule, 24 or ECC_GameTraceChannel11 in the pinned build), `Mobs: EVE passes through characters: walls open` and `Mobs: EVE meets characters: walls solid` when Stellar Blade's own pass-through (`bIgnoreCharacterCollision`, set during her evades) changes, `Mobs: released N (stale)` (or `link lost`, `error`, `retry`, `F11 return requested`), `Mobs: error (n/3): ...` (three errors stop new walls until the Lua mod reloads) and `Mobs: release failed, retrying: ...`; `STOP: Mob walls paused: ...` reports an unexpected failure. Minecraft logs `Mob walls not delivered to Stellar Blade: ...` when it cannot write `eve-mobs.txt`.

Lua logs Stellar Blade's HUD items as `HUD: widget search T ms, missing W, next in S s` for its first widget search and any slower than 5 ms (W: the widgets still missing among heal, util, lower, dash and bullets), `HUD: heal <texture> c/max cat k use u; util <texture> c cool x use u; lower <texture> c; bullet <alias> c; dash x` when a value read changes (a cooldown where it starts and ends, the ammo where it appears or goes; lower is `WB_MainHUD_Lower1Item`, logged to learn what it shows; `<texture>` is the item texture the slot draws, `-` for none, as for the heal slot's Tumbler cup; k is the heal slot's `ChangeItemCategory`, 12 for the Tumbler; u is the slot's `UseActive`, false while Stellar Blade blocks its use), `HUD: <kind> used (a -> b)`, `HUD: util slot changed from <texture> at 1 to <texture> (a last use is not counted)`, `HUD: read failed: ...` once per message and `HUD: consume request seen (n)` for the first five item-consume requests (a probe that may never fire in single player), per Lua lifetime at most 150 read lines and 200 others; `STOP: HUD slots paused: ...` reports an unexpected failure. Minecraft logs its first 20 conversions as `EVE item: kind, N entities` (a Smart Mine when it goes off), and `/stellaravatar status` adds `Items: HUD file fresh|stale|missing; uses converted: ...` (stale: older than 2.5 seconds; missing: no valid file of the link's session, or EVE does not replace the player), then `HUD: WxH @G, panel J/G, HP N columns.` from the last frame that drew Stellar Blade's HUD: the scaled window and GUI scale, the panel's screen pixels per panel pixel (J, at most G, at least half of it; one panel pixel is a third of Stellar Blade's dot tile) and the HP bar's columns, or `HUD: not drawn yet.`

The native adapter answers each [wardrobe request](../protocol/README.md#wardrobe) in `eve-wardrobe.txt` in the bridge directory (it keeps the newest one after the session); its `RESULT` line says what happened. `listed`: the owned list only. `equipped` or `unequipped`: Stellar Blade's worn map showed the change within a second. `unchanged`: the slot already held that state (no call), or Stellar Blade's own item rules refused it silently (a second exospine of one family, a DLC item, a suit change blocked by a state) or did not apply it within the second. `refused not-playing`: Lua's permit is not active for this stream's run (Stellar Blade paused, a cutscene, not entered, or another run). `refused not-ready`: no game world, table manager, spawned player actor, item manager or Inventory bucket. `refused fault-<stage>-<code>`: a read of Stellar Blade's memory or one of its own calls raised a structured exception, contained, during that step (`owner` for the checks of `not-ready`, `tachy`, `fusion`, `combat` and `slot` for those refusals below, `item` for `not-owned`, `equip` or `unequip` in Stellar Blade's call, `done` while waiting for the worn map, `list` for the owned list), with the exception code in hex (`c0000005`: an access violation); the toast shows both. `refused tachy`, `fusion` or `combat`: the checks Stellar Blade's equipment menu makes before it opens a slot, so its own menu would refuse too (the combat test also looks at an engaged enemy within its interaction distance). `refused slot`: v1 keeps to occupied slots, the earring and the face accessory, and never empties the suit or the hair. `refused not-owned`: the item is not in EVE's Inventory bucket or does not belong in that slot. No answer means the request was not taken: another session, a SEQ already taken, older than 2.5 seconds, no active pose stream, or an adapter older than the wardrobe.

Minecraft's pause menu shows an "EVE's equipment" row under "Back to Game" while EVE replaces the player (not under F3+Esc); the rows below move down. The screen sends `list` when it opens and one equip or removal at a time, its entries disabled until the answer with that SEQ arrives; each answer is logged as `Wardrobe request N: <result> [reason], K items`, and a change or refusal shows as a toast. After 5 seconds without it the screen says the adapter does not answer (`Wardrobe request N: no answer`, or `unreadable answer` when the file it found did not parse), and stays disabled until it is opened again: see the no-answer causes above, an adapter older than the JAR among them. Entries follow the adapter's rules: an item worn in another slot (a second gear or exospine) is shown with its badge but not moved, an item whose catalog meshes exceed 256 bones is disabled (`Not supported yet (bone limit)`), and an item whose meshes are missing from the pack stays clickable with the warning `Not in your avatar pack: rebuild it with both games closed` (the world then draws EVE without that part, which the live avatar's `skipped` line names). An item bought since the pack was last built shows that warning until the next install. The preview draws EVE's live pose with the studio camera of `avatarRenderCheck` (2.8 blocks away looking at 0.85 for the body, 1.0 at 1.45 for the hair, earring and glasses slots), at full block light without a sun, and turns by dragging. It uses her own shaders even under a shader pack, since the GUI draws after the pack's frame; if a pack hides her there, `/stellaravatar shading entity` draws the preview through Minecraft's entity programs too.

While `/stellaravatar live` or `/stellaravatar play` streams EVE's pose to the entered link and no capture (F1, F2, F4, `/stellarview livehd`) or native visuals (Shift+F8) run, Stellar Blade stops drawing its 3D world to leave the GPU to Minecraft; its window shows the HUD over black. Each of EVE's and her drone's streamed meshes first gets an `AlwaysTickPoseDistance` of 100 km, so it keeps ticking its pose unrendered (her body otherwise ticks only while drawn). Lua logs `Render: SB world drawing off (pose ticking kept on N meshes)` when it starts, `Render: SB world drawing on` when it ends (the stream stops or lapses, the link is left, a capture or native visuals start, or the bridge tick fails), `Render: SB world drawing kept on: ...` when it could not start (nothing stays changed) and `Render: SB world drawing restore failed: ...` while a restore is retried, each once per change, and `Render: restoring the cut a Lua reload left` when Lua, reloaded during a cut, finds it still set (the next line says whether drawing came back); F6 adds the current state. Stellar Blade sets the same flag itself at times; Lua never clears it when Stellar Blade had set it before the cut. A pose that freezes about a second after the `off` line means something rewrote the guard; `/stellaravatar off` brings drawing back.

### Ponytail resets

`/stellaravatar status` continues its `Cloth:` part, over the whole stream run (model rebuilds included, the stale count too): `Bones instead: F frozen (S samples), A absent (S), M mismatched (S), I invalid (S), R at a model rebuild.` counts the switches from Stellar Blade's cloth to bones by reason and the samples each kept on bones; `Particles changed in X% of cloth samples, her head in Y%.` is how often Stellar Blade's cloth and her head moved between the samples Minecraft read; `Stale runs ended by moving particles: a of 1, b of 2-5, c of 6-29, d of 30+; longest L.`; `Jumps over 30 cm: J after unchanged particles (largest P cm), K while they moved (largest Q cm).` compares every 64th particle in component space between consecutive cloth samples. Minecraft's log names the first 120 switches and jumps of a run, then says `Cloth: further cloth switches and jumps not logged.`: `Cloth: bones from sample C, frozen (particles unchanged for T ms over N samples while her head moved)` (or `absent (no cloth in the sample; component status 0xS)`, `mismatched (...)`, `invalid (...)`), `Cloth: bones at the model rebuild for generation G`, `Cloth: Stellar Blade's cloth back at sample C after N samples (T ms) on bones; its measured particles moved D cm` and `Cloth: jump of D cm at sample C after K unchanged samples (T ms)` or `... while the particles moved`; C is the pose counter, T Stellar Blade's publication times.

### Shader packs

Experimental, not yet validated in game (no Iris build has been installed yet). While an Iris shader pack is in use, EVE is drawn through Minecraft's cut-out and translucent entity programs and the additive eyes program, which the pack replaces with its own (see the [architecture](architecture.md)); the log says `EVE avatar: drawing through Minecraft's entity programs (shader pack in use).` and, once the pack is off, `EVE avatar: drawing with her own shaders.` The first draw with each program logs `EVE avatar: Minecraft program NAME (ID) reads INPUT=array|constant ...`; under a pack, Iris's program names and `iris_` inputs show that the pack replaced Minecraft's programs. Under a pack:

- the pack lights, fogs and post-processes her as an entity from her base color only: normal, surface (occlusion, roughness, metallic, specular), emissive, subsurface and hair maps and the reflected sky are not used;
- cut-out sections use the entity alpha test (alpha 0.1) instead of 0.5 (0.25 for hair), so hair edges look denser and the faint fringes of some hair cards and pins can show light;
- translucent overlays (eye light, tear line, eye shadow, teeth occlusion) blend through the translucent entity program as they blend in her own shaders; the sword edge's glow is its texture times its streamed tint and opacity, added like glowing eyes;
- the sword trail and the effect sprites are added through the eyes program (the trail with its glow baked into a gray texture); packs usually treat that as emissive;
- she casts her shadow through the pack's shadow pass while she replaces the player, in first person too (her opaque and cut-out sections, with the entity alpha test, so the hair's shadow is a little fuller; the pack's `shadowEntities` and `shadowPlayer` settings decide, as for the player). The first such draw logs `EVE avatar: Minecraft program shadow_entities_cutout (N) reads ...`. Replays and the two-blocks-ahead placement keep the player's own shadow. Packs that tessellate entities may not draw her;
- the hurt flash, combat, lock-on, HUD and camera are unchanged; the lock-on outline is Minecraft's glowing outline, which depends on the pack.

Fabulous graphics need nothing special: EVE draws into Minecraft's main framebuffer before its transparency composition, so translucent blocks in front of her composite correctly; the additive trail and sprites, which write no depth, can be covered by translucent blocks that stand behind them (between them and the background), while glass in front of her covers her and the trail as it should. `./gradlew avatarRenderCheck` with a last argument `entity` renders through Minecraft's own entity programs from the client jar (no pack), with the sword glow, to check this path offscreen. A camera argument may add a fourth value, the height it looks at. `sun=ELEVATION,AZIMUTH` (degrees, azimuth from +Z toward +X) puts a floor, a three-block wall and a slab around her, lights her with that sun, draws her cast shadow and prints the GPU time of her draw, her shadow map and the cast faces; with `entity`, it draws instead what the pack's shadow pass receives: her opaque and cut-out sections seen from that sun.

## Performance measurements

Each layer reports its own rate. Compare runs only at the same Minecraft framebuffer size, because capture cost grows with captured pixels.

- **Stellar Blade:** while a link is entered, `UE4SS.log` receives one `Cadence:` line per ten native seconds: native FPS, whether capture is live, completed generations and native frames from submission to observed completion. Idle lines give the same session's uncaptured rate.
- **Native adapter:** the private `eve-raw-timing.txt` keeps per-plane rows for the first 12 generations and rewrites whole-run summaries at most once per second. `COST 0`/`COST 2` are color/depth conversion times, `GAP` is the time between a generation's two plane arrivals: the second engine readback plus any image-queue wait, and `PERIOD` is the interval between publications. Values are count, mean and maximum microseconds.
- **Minecraft:** `/stellarview status`, also logged when a view stops, gives displayed frames, frames that arrived from the worker, frames replaced before the next Minecraft render or rejected as stale or mismatched, Minecraft world renders per second while the view is requested, and worker copy and texture-upload times. Upload time is the render-thread call cost, not GPU completion.

GPU contention between the games is outside these counters; sample it externally, for example with `nvidia-smi pmon`.

## Reverse terrain and texture probes

The reverse renderer displays Minecraft faces inside Stellar Blade and leaves its surroundings visible. It supports air and full cubes of stone, dirt, grass without snow, white wool and bedrock within the 9 × 6 × 9 blocks around the anchor, while the terrain window still contains them (once it has followed EVE away, Lua refuses them). Unsupported blocks stop visual publication. Textures come from the active Minecraft resource manager; no game assets are packaged here. It does not import mobs, distant chunks, arbitrary models or fluids.

After `/stellar start`, F5 and F8, toggle it with `sbmc visuals`. Disable it before capturing EVE into Minecraft. Visual revisions are independent of collision revisions; changing wool to stone can update appearance without changing collision. F11 removes owned visuals and performs the guarded return.

The standalone `sbmc texture` probe requires `minecraft-stone.png` in the private bridge directory, extracted from `assets/minecraft/textures/block/stone.png` in the user's own Minecraft 1.21.1 client JAR. It creates one temporary non-colliding cube ahead of EVE. Its opaque display material does not establish Minecraft lighting compatibility.

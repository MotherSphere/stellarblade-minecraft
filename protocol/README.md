# Shared protocol

The shared directory is private to the local user (0700). Text snapshots are bounded and versioned. Readers validate complete-message footers, identity, timestamps, revisions, dimensions and finite coordinates before using a snapshot. Implementations and shared [fixtures](fixtures/) are authoritative for exact grammars and bounds.

| Product | Producer | Reader | Contract |
|---|---|---|---|
| Terrain | Minecraft | Lua | `SBMC 1 TERRAIN`, fixed anchor, revision and merged boxes |
| EVE position | Lua | Minecraft | `SBMC 1 EVE`, session, state, acknowledged terrain revision and feet position |
| Native terrain visuals | Minecraft | Lua | Independent visual revision and supported face/texture data |
| Capture request | Minecraft | Lua/native | `SBMC_CAPTURE_SESSION 2`, RUN, SESSION, TIME, SIZE, STATE, END |
| Raw frame | Native | Minecraft | Mapping v1 containing frame-v6 metadata, RGBA8 and R32F depth |
| Control permit | Lua | Native | `SBMC_CONTROL 1`, run/session, generation, sequence and native context |
| Input / acknowledgement | Minecraft / native | Native / Minecraft | `SBMC_INPUT 1`, ordered edges, epochs, sequence and leases |
| Pose request | Minecraft | Lua/native | `SBMC_POSE_REQUEST 1`, RUN, TIME, STATE, END |
| Pose components | Lua | Native/Minecraft | `SBMC_POSE_COMPONENTS 1`, generation, placement and EVE's skeletal mesh components |
| Pose | Native | Minecraft | Pose mapping v1 with world, component-space bone and morph-weight floats |
| Combat event | Minecraft | Lua | `SBMC_COMBAT 1`, SESSION, SEQ, TIME, EVENT and attacker yaw, END |
| Lock-on target | Minecraft | Lua | `SBMC_LOCK 1`, SESSION, SEQ, TIME, TARGET position or `none`, END |

Positions use Unreal `(X,Y,Z)` to Minecraft `(X,Z,Y)` with 100 Unreal units per block and the session's anchor transform. Native camera/depth and feet position must match the terrain link; mixing older coordinate bases is unsupported.

## Raw mapping v1

Minecraft exclusively creates `eve-frames-<RUN>.bin` with mode 0600. RUN and SESSION are separate 32-character lowercase hexadecimal identities. Each run fixes width 1–3840 and height 1–2160. Let `P = width * height`, `stride = align64(4096 + P * 8)`, and `total = 4096 + 3 * stride`. Integers and float planes use little-endian layout.

| Header offset | Field |
|---|---|
| 0 | Eight-byte magic `SBMCFRM1` |
| 8, 12 | Version 1; header size 4096 (u32) |
| 16, 20, 24, 28 | Width, height, slot stride, total bytes (u32) |
| 32, 64 | RUN and SESSION (32 ASCII bytes each) |
| 96 | Consumer PID (u32) |
| 128 | Atomic middle-slot index with dirty bit 4 (u32) |
| 192, 196, 200 | Producer PID, state, error (u32) |
| 208, 216 | Producer Unix milliseconds and completed counter (u64) |
| 256, 264, 272 | Consumer state (u32), Unix milliseconds and accepted counter (u64) |

Reserved bytes are zero. Producer states are 0 unclaimed, 1 ready, 2 released, 3 failed. Consumer states are 1 active, 2 stopped. Producer PID `UINT_MAX` marks a cancelled unclaimed run. Claims and cancellation use the same atomic word.

Initially the producer owns slot 1, consumer slot 2 and middle slot 0. Atomic exchange transfers middle ownership; a published middle sets dirty bit 4. The reader copies its acquired slot before exchanging again. A slot contains counter (u64) at 0, publication Unix milliseconds (u64) at 8, metadata length (u32) at 16, format 1 (u32) at 20, ASCII frame-v6 metadata at 64, RGBA8 at 4096, then P R32F depth values. Metadata is limited to 2048 bytes.

A frame-v6 generation is exactly two registered image jobs, color and depth, in either order; a `MASK depth 0` line records that no coverage job exists. Alpha is 255 where depth is positive and below 65504 (the binary16 capture clear value) and 0 elsewhere. Non-finite or non-positive depth becomes 0. A retired mask job fails the run. No mapped slice escapes the Java reader. Native release acknowledgement is required before deleting an active producer's mapping; an unresolved mapping is retained and never reset for another run.

## Pose stream v1

Minecraft refreshes `eve-pose-request.txt` (`SBMC_POSE_REQUEST 1`, RUN, TIME in Unix milliseconds, STATE `active` or `stopped`, END) at least every second; a request older than three seconds is inactive. While it is active, Lua publishes [`eve-pose-components.0/1`](fixtures/pose-components.txt) a few times per second when the composition changes: RUN, a GENERATION that increases within the run, the entered link's SESSION and `ANCHOR x y z unitsPerBlock` (Unreal) or `none`, `CONTROLLER object class offset pawn pawnClass yawScale pitchScale` (the local player controller, the byte offset of its `ControlRotation` as 8 hex digits, aligned, below 0x4000, its pawn and the pawn's class, and the controller's `InputYawScale` and `InputPitchScale` as decimal floats, finite with magnitude 0.01 to 100) or `none`, COUNT (1–16), then per component its object, class and skeletal mesh addresses (16 lowercase hex digits), bone count (0 for leader-pose followers, at most 256), morph count (at most 1024), name, mesh name and leader or `-`, followed by `BONES` (component-space order) and `MORPHS` (`MorphTargets` order) name lines, then `PARAMETERS n` (0–32) and per parameter `PARAMETER index component slot name object class offset element nameIndex floats`: a glow parameter (`Opacity`, `Emissive_Intensity`, `Emissive_Color` and their `_2` pairs) of a `MaterialInstanceDynamic` on that component's material slot, with the byte offset of its `ScalarParameterValues` or `VectorParameterValues` array (8 hex digits, 8-aligned, below 0x4000), the element index (below 1024), the FName comparison index expected at the element (positive) and 1 (scalar) or 4 (vector) floats; then `EFFECTS none` or `EFFECTS children asset template activeByte activeMask niagaraClass particleClass n` (byte offsets of `USceneComponent::AttachChildren`, `UNiagaraComponent::Asset` and `UParticleSystemComponent::Template` as 8 hex digits, 8-aligned, below 0x4000; the byte of `UActorComponent::bIsActive` and its mask as 2 hex digits; both component classes) and per effect asset `EFFECT index asset name`, at most 32. Readers take the newer complete slot of their run.

The adapter reads the listed components on the game thread at the verified gameplay XInput poll, after the previous frame's animation and physics. A component is read only while it is the live, non-pending-kill `GUObjectArray` object at its address with the published class and mesh; otherwise its status is 0. The controller is checked the same way (class only). Faults are contained. While a table with an anchor is published for an active request, Lua grants the native input permit to RUN and that SESSION, as it does for a continuous capture.

Minecraft exclusively creates `eve-pose-<RUN>.bin` (0600, 200704 bytes): the raw mapping v1 header and ownership protocol with magic `SBMCPOS1`, slot stride 65536 at offset 16, payload capacity 16352 floats at 20, total bytes at 28, RUN at 32 and no SESSION. Offsets 224, 228 and 232 hold the producer's last and maximum read time (u32 microseconds) and total read time (u64). With each slot the producer also writes EVE's gauges: five f32 at 324 (Beta, its maximum, Burst, its maximum, the Burst unlock stat), then state 1 at 320, or state 0 when they cannot be read. They come from Stellar Blade's native player actor (game world global at RVA 0x7032570, actor manager +0xc8, actors +0x28 indexed by the player index +0x3c below the count +0x30, stats as floats at +0x118 + 4 × `ESBActorStatType`: 14, 15, 18, 19, 116), only while its life state (+0x2600) is 1 or 6, each finite within 0–100000 and the gauges within their maximums. After the claim, Minecraft may write its camera: Unix milliseconds (u64) at 288, Unreal Pitch and Yaw (two f32 as one atomic 64-bit word) at 296 and state 1 at 304. While forwarded input belongs to the same RUN, the adapter turns the game's camera toward a look no older than 200 ms, with finite angles and pitch within ±90 degrees. Yaw goes through the pawn's `AddControllerYawInput` (the game's own look input path, divided by the published scale): each frame Minecraft's motion since the previous frame plus 15 % of the remaining gap to `ControlRotation`, at most 45 degrees. Pitch goes to the game's camera dolly, which carries its camera pitch (`ControlRotation`'s pitch does not track it), while the arm's next pitch follows the dolly's alpha alone: the pawn's `CameraBoom` (+0x5c0) is a live object whose virtual table is `USBSpringArmComponent`'s (RVA 0x5ce42a0) and whose owner (+0xb0) is the pawn; it uses the dolly (`bUseCameraDolly`, +0x2f4) with a `CameraDollyTrackData` (+0x2f8), is in dolly mode (`bLastUseCharacterControllerRot`, +0x370, clear), is not easing its rotation after a mode change (`RemainBlendCamera`, +0x374, at most 0), has no rotation lag (`bEnableCameraRotationLag`, bit 6 of +0x284), is on its default spline (`CurrentDollyMode`, +0x3e0, −1) and blends none (`DollyBlends` count, +0x3d8, 0); the pawn is neither aiming (`bTPSMode`, +0x1528) nor fishing (`FishingModeType`, +0x1690), and its slope camera does not set the alpha (it does while, in `MovementCheckInfo` at +0x1770, `CameraSlopeMoveType` +0x3ec and `bRunCameraSlopeMoveAlpha` +0x3ed are set and `CurrentCameraSlopeMoveRunningTime` +0x3f4 exceeds `CameraSlopeRunTimeFromStart` +0x3fc). Then the adapter adds 1/300 per degree from the arm's last pitch (`PreviousDesiredRot.Pitch`, +0x2c0, taken within ±180) to Minecraft's to `CameraDollyAlpha` (+0x2f0, kept within 0–1), ends the game's dolly blend (+0x3c0..+0x3c7 = 0, +0x3c8 = −1) and sends no pitch input. Otherwise Minecraft's pitch motion goes through `AddControllerPitchInput` (divided by the published scale, at most 45 degrees). Minecraft writes yaw within one turn. After 60 consecutive frames with a yaw gap above 30 degrees the adapter stops adding look input until the gap closes; it still sets the dolly meanwhile. The pawn must be the live object of its published class, with its virtual table and both functions inside the game image. A slot holds counter (u64) at 0, publication Unix milliseconds (u64) at 8, generation (u64) at 16, format 1 at 24, component count at 28, payload floats at 32, controller status at 36 (bit 0 rotation read, bit 1 camera turned toward Minecraft's this frame, bit 2 camera dolly set from Minecraft's pitch this frame) with its Pitch, Yaw and Roll (f32 degrees, read before this frame's turn) at 40 and, with bit 2, the camera's Unreal pitch (f32 degrees, read before the dolly was set) at 52, else zero, one status word per component at 64 (bit 0 world, 1 bones, 2 morphs) and the payload at 128: per component its world transform, its bone transforms in component space, then its morph weights; after the last component, each parameter's floats (zeros unless the instance is live with its class and the element still carries the name; elements are 36-byte scalar or 48-byte vector parameter values, value at +16); then, with effects, 8 records of 11 floats: the index of an active effect's asset (-1 for none) and its component's world transform, for live Niagara or Cascade components of those classes attached directly to a live listed component, active and playing a listed asset. A transform is 10 floats: quaternion xyzw, translation xyz, scale xyz, Unreal space. Minecraft decodes a slot only with the table of the same generation.

## Combat events

On each damage to the bridged player from an attacker or projectile, Minecraft replaces [`eve-combat.txt`](fixtures/combat-event.txt): SESSION (the terrain link's), SEQ (increasing within the session, repeated by `END`), TIME in Unix milliseconds, then `EVENT kind yaw` with kind `perfect_dodge`, `perfect_parry`, `guard` or `hit` and the Unreal world yaw in degrees (one decimal, within ±180) from EVE toward the attack's origin, or `none`. A plain dodge publishes nothing. Lua reads it each native frame and acts once per SEQ, only for the entered link's session and within 2.5 seconds of TIME: a perfect dodge plays EVE's `CH_P_EVE_01/Skill/P_Eve_Sword_Normal_JustEvade1` Show through her `SBShowActorInterface.PlaySingleShow`, toward a point 3 m along the yaw, with its full-body key's `bStopAtMove` lifted until the key has started (restored 0.2 s later, retried every frame), since the game's skill blocks movement during it and a lone Show does not; if no new evade effect is on her body mesh 0.2 s later, Lua sets Stellar Blade's global time dilation to 0.3 for half a second of real time (unless the game already runs dilated) and plays the evade Niagara systems instead; a guard or perfect parry plays the `Result/Result_Guard` Show, a perfect parry also its parry system; a hit with a yaw makes EVE react, at most every 0.6 seconds and one at a time, through the stock `Hit/Result_Hit_Stand_LightAttack` Show by one of three variants (`SBBlueprintLibrary.PlaySBShowToPlayerCharacter`; `PlaySingleShow` with the side's key `bCheckHitLevel` lifted in memory; `PlaySingleShow` with `AdditivePlay` counted into EVE's transient `ShowKeyTagMap`), each undone 1.1 s later and retried until it is; variants take turns until one shows a custom-animation alpha from none before, which is kept, and stop after 12 counted tries without one (a try while EVE already animates or moves is not counted). The perfect-dodge Show applies its Effect keys as in the game (invulnerability while it plays, Burst gauge, the just-evade counter flag); the other Shows have no Effect or SkillResult key. Leaving the link restores time at once; a failed restore is retried every frame. Stopping the bridge deletes the file.

## Lock-on target

While Minecraft's lock-on holds a target, it replaces [`eve-lock.txt`](fixtures/lock.txt) every 50 ms: SESSION, SEQ (increasing, repeated by `END`), TIME in Unix milliseconds and `TARGET x y z`, the target's centre in blocks relative to the bridge origin (Minecraft axes, three decimals, within ±4096), or `TARGET none` once released. Lua takes a newer SEQ of the entered link's session (a first one only within 2.5 seconds of TIME) and keeps the lock for 0.6 seconds after the newest: it spawns a hidden, collisionless, tickless bare `SBCharacter` with an enemy tribe of EVE's (`SupplyNPC` for `PC`), keeps it at the target's Unreal position (anchor + (x, z, y) × scale), sets EVE's `LockOnCharacter` and `bLockOn` with Stellar Blade's lock-on camera off (`bLockOnCameraEnable`) and clears her off-screen timer each frame, so Stellar Blade's own lock-on faces and strafes her, and draws her sword with Stellar Blade's own draw and unfold Shows, checked every second while the game is not in battle and does not force it folded (a draw that did not stick is retried with the draw's attach event sent at once, five tries in a row at most) and sheathed once on release if Lua drew it; a lock the game drops is engaged again at once, then at most every 0.25 s while the game refuses it; spawn, follow and engage errors together stop new locks after three. Release, staleness, link loss, F11 or an error releases through the game (target unavailable), restores the camera flag and destroys the proxy, retried every frame until done. The native adapter reads the same file: while it names a target with a TIME at most 0.6 s old and input is forwarded, EVE's lock-gated evade commands take Stellar Blade's lock-on rows (side steps) instead of the plain ones, since the game's own lock target stays empty; each changed command flag is restored on release, staleness or the end of forwarding (one out of her command tree at that moment once it is back). Stopping the bridge deletes the file.

## Text publication and legacy captures

Java publishes text with atomic replacement. Lua uses alternating slots where Windows cannot rename over an existing destination. Control permits retire the old slot under a unique owned name before publishing; cleanup failure retains ownership for retry. A missing/stale permit neutralizes input.

Frame-v1 uses PNG color; v2 uses BMP color with PNG mask and HDR depth. Frame-v3 describes a pending asynchronous still and v4 the encoded continuous compatibility path. Frame-v5 described three-job raw payloads and is no longer accepted; v6 replaces it. Pending encoded output requires observed file closure and content validation; metadata alone is insufficient. The active `/stellarview play` and `/stellarview livehd` path uses v6.
